APB Slave DUT Functional Verification using SystemVerilog UVM

Project Overview
This project focuses on the functional verification of an AMBA APB (Advanced Peripheral Bus) Slave DUT using SystemVerilog and UVM (Universal Verification Methodology).

A complete UVM-based verification environment is developed to verify the APB Slave DUT for correct read/write operations, wait-state handling, error responses, and boundary conditions.


     Verification Objectives

The main objectives of this project are:

- Verify APB read and write transactions.
- Verify correct APB protocol behavior.
- Verify wait-state handling.
- Verify error response generation for invalid accesses.
- Verify boundary and corner cases.
- Compare DUT output with expected behavior using a scoreboard/reference model.
- Improve verification completeness using functional coverage.
- Use UVM methodology to create a reusable and structured testbench.



     DUT Description

The APB Slave DUT implements an APB-compliant slave interface and provides register-based read/write functionality.

     APB Interface Signals

 Signal  Description 

 `PCLK` | APB clock |
 `PRESETn` | Active-low reset |
 `PSEL` | Slave select |
 `PENABLE` | Enable phase signal |
 `PWRITE` | Read/write control |
 `PADDR` | Address |
 `PWDATA` | Write data |
 `PRDATA` | Read data |
 `PREADY` | Transfer ready signal |
 `PSLVERR`  Slave error response 


UVM Components

The testbench contains the following major UVM components:

1.Sequence Item
Defines the APB transaction fields such as:

- Address
- Write data
- Read data
- Write/read control
- Select and enable information
- Expected response

2.Sequence

Generates APB transactions for different verification scenarios.

Examples:

- APB write sequence
- APB read sequence
- Invalid access sequence
- Wait-state sequence
- Boundary-condition sequence

3.Sequencer

Controls the flow of sequence items from the sequence to the driver.

4.Driver

Converts the transaction-level APB sequence items into pin-level APB signals and drives them to the DUT.

5.Monitor

Observes APB interface activity and converts signal-level transactions back into transaction-level information.

6.Scoreboard

Compares the actual DUT response with the expected response generated by the reference model.

Reference Model

Predicts the expected DUT behavior for a given APB transaction.

7.Agent

The APB agent contains:

- Sequencer
- Driver
- Monitor

8.Environment

The UVM environment integrates the APB agent, scoreboard, reference model, and coverage components.

9.Test

Controls the overall verification flow and starts the required sequences.


    Verification Scenarios

The following scenarios are verified:

APB Write

- Valid address
- Valid write data
- Correct APB setup and access phases
- Successful write operation

APB Read

- Valid address
- Correct read operation
- Verification of returned `PRDATA`

Wait States

- DUT holds `PREADY` low
- Master waits until the slave is ready
- Transfer completes when `PREADY` becomes high

Error Response

- Invalid or unsupported access
- Verification of `PSLVERR`
- Verification of appropriate response from the DUT

Boundary Conditions

- Minimum/maximum register addresses
- Read/Write Only Registor
- Repeated read/write operations
- Different data patterns
- Reset and post-reset operations

    Verification Result

The testbench is used to verify the APB Slave DUT across different functional scenarios.

Successful verification is determined by:

- Correct APB read/write behavior
- Correct wait-state handling
- Correct error response
- No unexpected DUT behavior
- Successful scoreboard comparisons
- Satisfactory functional coverage
